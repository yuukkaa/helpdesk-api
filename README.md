# Веб-сервис технической поддержки (Help Desk) — REST API + React Client

Полнофункциональный веб-сервис технической поддержки (Help Desk), состоящий из серверной части на **Laravel 13 (REST API + Sanctum)** и клиентского SPA-приложения на **React + TypeScript + Vite**.

---

## 1. Описание проекта и сущностей API

Сервис автоматизирует приём, классификацию, распределение и обработку обращений пользователей в службу технической поддержки.

### Основные сущности:
1. **Пользователи (`User`)** — учётные записи с ролевой моделью доступа:
   - `client` — создание обращений (с прикреплением файлов/изображений), просмотр своих заявок, переписка со специалистами, чтение опубликованных статей базы знаний;
   - `support` — просмотр всех заявок с фильтрацией и сортировкой, взятие обращений в работу, смена статусов по графу переходов, редактирование заявок, ведение внутренних служебных заметок (`is_internal`), управление метками и базой знаний, просмотр статистики и выгрузка отчётов в CSV;
   - `admin` — полный доступ, включая управление справочником категорий, учётными записями пользователей, принудительное назначение исполнителей и удаление заявок.
2. **Заявки (`Ticket`)** — основная сущность системы. Содержит тему (`subject`), описание (`description`), категорию, автора, ответственного специалиста (`assignee`), приоритет (`low`, `medium`, `high`, `urgent`) и статус жизненного цикла (`new` → `in_progress` ↔ `waiting_for_client` → `resolved` → `closed`).
3. **Категории (`Category`)** — тематический классификатор обращений («Доступ и пароли», «Оплата и счета», «Технические ошибки», «Общие вопросы»).
4. **Сообщения (`Message`) и Вложения (`Attachment`)** — переписка внутри заявки с поддержкой внутренних служебных заметок для сотрудников и прикрепления файлов/изображений (`FormData`) через `Storage` (`public`).
5. **Метки (`Tag`)** — связь «многие-ко-многим» (`tag_ticket`) для гибкой маркировки заявок (`#срочно`, `#баг`, `#аккаунт`, `#бухгалтерия`).
6. **База знаний (`KnowledgeBaseArticle`)** — справочные статьи и инструкции для самообслуживания клиентов и формирования ответов специалистами (включая RAG-черновики через ИИ Gemini).

## 3. Порядок запуска сервера Laravel и клиента

Для работы приложения необходимо запустить два процесса в отдельных терминалах: сервер API на Laravel и клиентское приложение на Vite.

### 3.1. Запуск сервера Laravel API (Терминал 1)
```bash
# 1. Установка зависимостей PHP
composer install

# 2. Копирование конфигурации окружения и генерация ключа приложения
cp .env.example .env
php artisan key:generate

# 3. Пересоздание таблиц БД и наполнение демонстрационными данными (12 заявок, пользователи, категории, теги, статьи БЗ и пример изображения)
php artisan migrate:fresh --seed

# 4. Создание символической ссылки для публичного хранилища вложений (storage/app/public -> public/storage)
php artisan storage:link

# 5. Запуск локального HTTP-сервера API на http://localhost:8000
php artisan serve --host=127.0.0.1 --port=8000
```

### 3.2. Запуск клиентского приложения React + Vite (Терминал 2)
Клиентское приложение расположено в каталоге `frontend/` и работает на порту `http://localhost:5173`. Базовый адрес API настраивается в `frontend/.env` (`VITE_API_BASE_URL=http://localhost:8000/api`).

```bash
# 1. Переход в каталог клиентского приложения
cd frontend

# 2. Установка зависимостей Node.js
npm install

# 3. Запуск dev-сервера Vite (http://localhost:5173)
npm run dev
```

Настройки CORS на сервере находятся в файле `config/cors.php` и используют переменную окружения `CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173` (аутентификация через заголовок `Authorization: Bearer <token>`, `supports_credentials = false`).

## 4. Страницы клиентского приложения и ключевой сценарий

1. **Вход и регистрация (`/login`)** — авторизация по email/паролю, регистрация нового клиента, быстрый выбор демонстрационных ролей и вывод ошибок валидации `422` под полями формы.
2. **Список заявок (`/`)** — таблица обращений с серверным поиском (`search`), фильтрацией по статусу (`status`), приоритету (`priority`) и категории (`category_id`), сортировкой (`sort`, `order` по клику на заголовки колонок и через селектор), пагинацией на основе блока `meta` (`current_page`, `last_page`, `total`) и выгрузкой отчёта в CSV.
3. **Модальная форма создания и редактирования заявки (`TicketFormDialog`)** — предварительная проверка обязательных полей на клиенте, отображение ошибок `422 Unprocessable Entity` (`errors`) рядом с полями, выбор категории из API (`/api/categories`), загрузка файлов и изображений через `FormData` (без заголовка `Content-Type: application/json`) и ИИ-классификация.
4. **Карточка заявки и ключевой сценарий (`/tickets/:id`)**:
   - просмотр связанных данных (автор, категория, исполнитель, метки, даты);
   - отображение загруженных изображений (`<img>`) и прикреплённых файлов;
   - переписка по заявке с поддержкой загрузки файлов (`FormData`), внутренних служебных заметок (`is_internal`, скрытых от клиента) и генерации черновика ответа ИИ;
   - блок ключевого сценария: взятие заявки в работу (`POST /api/tickets/:id/assign`), переходы по графу статусов (`PATCH /api/tickets/:id/status`), управление метками и вывод баннера при нарушении бизнес-правил (`409 Conflict`, поле `message`) или отказе в доступе (`403 Forbidden`);
   - редактирование заявки (`support`, `admin`) и удаление заявки с подтверждением (`admin`).
5. **База знаний (`/knowledge-base`)** — поиск и фильтрация справочных статей по категориям, создание, редактирование и удаление статей для сотрудников поддержки и администратора.
6. **Раздел администратора и аналитики (`/admin`)**:
   - управление категориями (`admin`) — создание, редактирование, удаление с подтверждением (при попытке удалить категорию с заявками выводится `409 Conflict`);
   - управление пользователями (`admin`) — фильтрация по роли, поиск, пагинация `meta`, создание, смена ролей и удаление с подтверждением;
   - сводная статистика и нагрузка специалистов (`/api/statistics/tickets`, лимит 5 активных заявок) + экспорт в CSV;
   - управление справочником меток (`/api/tags`) и проверка серверной защиты (`403 Forbidden`).

Скриншоты всех страниц клиента и прохождения ключевого сценария сохранены в каталоге [`docs/screenshots/`](docs/screenshots/).

1. **Подробная документация и таблица тест-кейсов:** [`docs/API_DOCUMENTATION.md`](docs/API_DOCUMENTATION.md)
